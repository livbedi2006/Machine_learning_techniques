## 1. Objective

This video demonstrates a **complete, simplified (toy) end-to-end ML pipeline** — from raw data to a working, deployable classification model — so that beginners can see how all the individual pieces of the **MLDLC (Machine Learning Development Life Cycle)** fit together in practice, before diving deep into each stage separately in later videos.

The problem used: **Predicting whether a student will get placed or not**, based on two simple numerical features — **CGPA** and **IQ**. This is a **toy dataset** (small and simple by design) so the focus stays on understanding the *workflow*, not on data complexity.

**Problem type:** Binary Classification (`Placed` = 1, `Not Placed` = 0)

---

## 2. The End-to-End Workflow Covered

```
1. Preprocess + Clean the data
2. Exploratory Data Analysis (EDA)
3. Feature Selection
4. Train-Test Split
5. Model Training (Logistic Regression)
6. Model Evaluation
7. Model Deployment (using Pickle)
```

This mirrors the **MLDLC** at a small scale — the same steps used in large, real-world ML projects.

## 3. Step-by-Step Code Walkthrough

### Step 1: Import Libraries & Load the Dataset

```python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

# Load the toy placement dataset
df = pd.read_csv('placement.csv')

df.head()
```

Typical structure of `placement.csv`:

| Unnamed: 0 | cgpa | iq  | placement |
|---|---|---|---|
| 0 | 6.8 | 123 | 1 |
| 1 | 5.9 | 106 | 0 |
| 2 | 5.3 | 121 | 0 |
| 3 | 7.4 | 132 | 1 |

### Step 2: Basic Data Cleaning

```python
# Drop the unnecessary index column that comes with the CSV
df = df.iloc[:, 1:]

df.head()
df.shape
df.info()          # check datatypes and null values
df.isnull().sum()  # confirm no missing values in this toy dataset
```

### Step 3: Exploratory Data Analysis (EDA)

Since there are only 2 input features, we can visualize the entire dataset directly using a scatter plot.

```python
plt.scatter(df['cgpa'], df['iq'], c=df['placement'])
plt.xlabel('CGPA')
plt.ylabel('IQ')
plt.title('CGPA vs IQ colored by Placement')
plt.show()
```

This single plot shows whether the two classes (`placed` / `not placed`) are **linearly separable** — which tells us a simple linear model like **Logistic Regression** is a reasonable choice.

### Step 4: Splitting Input (X) and Output (y)

```python
X = df.iloc[:, 0:2]   # cgpa, iq  -> input features
y = df.iloc[:, -1]    # placement -> target/output

X.head()
y.head()
```

### Step 5: Train-Test Split

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.1, random_state=1
)

X_train.shape, X_test.shape
```

### Step 6: Feature Scaling

Logistic Regression is sensitive to the scale of input features, so we standardize them.

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()

X_train = scaler.fit_transform(X_train)   # fit on train, then transform train
X_test = scaler.transform(X_test)         # only transform test (no fitting again!)
```

> **Important rule:** Always `fit_transform()` on the training data only, and `transform()` (not fit) on the test data — this prevents **data leakage** from the test set into training.

### Step 7: Model Training

```python
from sklearn.linear_model import LogisticRegression

clf = LogisticRegression()
clf.fit(X_train, y_train)
```

### Step 8: Prediction & Evaluation

```python
y_pred = clf.predict(X_test)

from sklearn.metrics import accuracy_score

accuracy_score(y_test, y_pred)
```

### Step 9: Visualizing the Decision Boundary (Optional but insightful)

```python
from mlxtend.plotting import plot_decision_regions

plot_decision_regions(X_train, y_train.values, clf=clf, legend=2)
plt.xlabel('CGPA (scaled)')
plt.ylabel('IQ (scaled)')
plt.title('Decision Boundary of Logistic Regression')
plt.show()
```

This shows visually **how the model separates** the "placed" vs "not placed" regions based on the two features — a great way to intuitively understand what the model has learned.

### Step 10: Model Deployment — Exporting with Pickle

Once the model performs well, it is **exported/pickled** so it can be reused later inside a web app (e.g., Flask/Streamlit) without retraining every time.

```python
import pickle

pickle.dump(clf, open('model.pkl', 'wb'))
```

**Loading it back later (in a separate script/app):**

```python
import pickle

model = pickle.load(open('model.pkl', 'rb'))

# Predicting placement for a new student: cgpa=6.5, iq=118
# Note: must apply the SAME scaler used during training before predicting
new_data = scaler.transform([[6.5, 118]])
prediction = model.predict(new_data)

print(prediction)   # Output: [1] -> Placed, or [0] -> Not Placed
```

## 5. Key Takeaways

- A **toy project** is a small, simplified version of a real-world ML problem, used purely to understand and practice the **end-to-end workflow** before tackling messier, larger real datasets.
- Even a 2-feature dataset can demonstrate the **entire ML pipeline**: data → cleaning → EDA → split → scale → train → evaluate → deploy.
- **Feature scaling must be fit only on training data**, then applied (not re-fit) to test/new data — critical to avoid data leakage.
- **Pickle** is a simple and common way to save a trained Scikit-learn model so it can be loaded instantly elsewhere (e.g., a Flask or Streamlit web app) without retraining.
- This same 7-step structure scales up to **any real-world classification/regression project** — only the complexity of each step increases (more features, bigger data, more preprocessing, hyperparameter tuning, etc.).
